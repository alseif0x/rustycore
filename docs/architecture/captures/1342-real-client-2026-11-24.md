### Transfer and `ObjectUpdateFailed`

Hearthstone's normal client cast reached `Player same-map near teleport initiated`
but did not emit `MoveTeleport`. C++ `Unit::SendTeleportPacket` sends that packet
to the moving player (`Unit.cpp:12208–12254`). Rust's near-teleport gate skips it
when `player_logout` is true.

C++ `WorldSession::HandleObjectUpdateFailedOpcode` calls `LogoutPlayer(true)`
when the failed object is the current player (`MiscHandler.cpp:1083–1095`). Rust
`wow-world-lifecycle/src/support.rs:243–265` currently only sets
`player_logout=true`; it does not execute that finalization. The C++ control did
not log this failure. The remaining `ObjectUpdateFailed` and its root cause are
open; this campaign does not claim that a reset alone repairs it.

## Repair included in this candidate

C++ `WorldSession::LogoutPlayer` clears `m_playerLogout` after every mode at
`WorldSession.cpp:691–694`. Rust only cleared it during `CharacterSelection`.
`wow-world-application/src/session_lifecycle/finalization.rs` now clears it in
the common `Release` path. The production-linked regression
`save::logout::production_disconnect_resets_player_logout_for_next_login` passed
with one test and 42 filtered out. This repair is evidence for the reset, not
acceptance of near teleport or of the separate `ObjectUpdateFailed` behavior.
