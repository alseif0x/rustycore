# Historical migration inventories

These are retained snapshots from the earlier refinement and represented-port
tracks. Use [STATE.md](../STATE.md), [PORT_PLAN.md](../PORT_PLAN.md) and the active
issue/checkpoint for current scope, dependency order and completion.

- `cpp-*`: source-file, opcode, statement, config, DB2 and script locators.
- `r2-*`: historical product scope, targets, WBS, divergences and test proposals.
- `r3-*`: historical cross-system registries, including the proposed E2E harness.
- `r4-*`: former DAG, ordering, implementation/smoke gates and temporary stubs.
- `r5-*` / `r6-*`: coverage audit and former next-miniphase selection.
- `r7-*` / `r8-*`: dated implementation/represented-state records and boundaries.
- `creature-port-matrix.tsv`: historical Creature coverage matrix.

The documentation cleanup of 2026-09-05 did not regenerate or change TSV rows,
membership, statuses, counts or schemas. Markdown notices clarify precedence;
removing unsupported prose does not create new canonical evidence. Technical
identifiers and provenance retained in data are not operating instructions.

Use individual rows to investigate a relevant historical question and contrast
current Rust/C++ before relying on them. No full inventory refresh, new row,
micro-issue or micro-PR is required merely to resume an authorized capability.
Do not reinterpret represented-item totals as integrated server parity.
